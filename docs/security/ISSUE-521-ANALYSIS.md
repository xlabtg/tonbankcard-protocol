# Разбор аудита #521 и план устранения

Дата исследования: 6 октября 2026. Родительская задача объединяет #503–#520; обсуждения всех подзадач прочитаны. Исправления не меняют эмиссию, модель non-custodial и право администраторов распоряжаться TBC. Проверяется весь путь: FunC → Tact → indexer → API → SDK → клиенты → CI.

## Исследованные готовые компоненты

- [TON core](https://github.com/ton-org/ton-core): уже используется; Address/CRC, Cell/BOC и StateInit устраняют собственные небезопасные парсеры.
- [TON Sandbox](https://github.com/ton-blockchain/sandbox): исполняет настоящий bytecode, поэтому отличает корректную сериализацию от treasury-заглушки.
- [node-postgres](https://node-postgres.com/features/queries) и [ioredis](https://github.com/redis/ioredis): параметризованный SQL, pool, SET NX; выбран существующий storage interface вместо нового ORM.
- [Redis SET](https://redis.io/docs/latest/commands/set/): NX acquisition подтверждается ответом OK. GET после проигранного SET не доказывает владение ключом.
- [TON NFT reference](https://docs.ton.org/contracts/standard/tokens/nft/nft-reference): `get_nft_data` является get-method, а `get_static_data` возвращает index/collection. Из этого следует необходимость явного owner-response extension, а не выдуманного стандартного TEP-62 owner callback.
- [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use) рекомендует промежуточные env для недоверенного текста; дополнительно ограничены ref и package version.
- [Advisory braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), обновлённое 2 октября 2026: затронуты ≤3.0.3, patched versions отсутствуют. [Picomatch](https://github.com/micromatch/picomatch) — вариант будущей миграции, но не drop-in замена public parse/expand API, используемого transitive dependencies. Переназвать непатченный пакет недостаточно: локальный fork содержит реальные guards и отдельные тесты.

## Ограничения эксплуатации

Resolver extension требует совместимого NFT item и сообщения регистрации от настоящей collection. Кэш consumer обновляется после подтверждённого refresh; перед выдачей прав новому владельцу нужно дождаться его обработки. Адреса mainnet не выдумываются: resolverAddress берётся из проверенного deployment manifest. Настройка reviewers GitHub environment требует административных прав и выполняется оператором перед публикацией. Ни mainnet deploy, ни публикация SDK этим PR не запускаются.
