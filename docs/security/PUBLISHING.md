# Публикация SDK

Ручная публикация разрешена только из `main`. Release/tag должен указывать на коммит,
принадлежащий `origin/main`; версия тега обязана совпадать с метаданными пакета.
Перед публикацией выполняются проверки типов, lint и тесты. Входы workflow передаются
через переменные окружения и проверяются до вызова npm.

В настройках GitHub environments `npm-publish` и `pypi` задайте required reviewers,
запрет self-review и ограничение deployment branches/tags на `main` и проверенные
release tags. Эти настройки хранятся на GitHub, YAML не может назначить reviewers.
Права OIDC выдаются только job публикации. Отдельный release trigger создаётся после
слияния PR; этот PR сам пакеты не публикует.

Проверка GitHub API 6 октября 2026 обнаружила только environment `preview`;
`npm-publish` и `pypi` ещё не настроены. Текущий токен имеет push/triage, без admin.
Поэтому оба publish job дополнительно прекращаются до публикации, если server-side
required reviewers отсутствуют, self-review разрешён или настройки нельзя прочитать.
Администратор создаёт gates перед следующей публикацией. Это оставшееся действие
в настройках репозитория; код не подменяет его фиктивным approval в YAML.
